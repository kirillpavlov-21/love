# Бэкенд «Куда идём?»

Небольшой сервер для функций, которым нужна общая память между людьми:

- **живые голоса компании** — друзья голосуют по одной ссылке, итоги обновляются сами, без пересылки ссылок туда-обратно;
- **колесо при ничьей** — у всех один и тот же результат;
- **ответы на свидание и «Мои приглашения»** — создатель видит, открыли ли приглашение и что ответили;
- **отзывы и рейтинги мест** — оценка 1–5, теги, «для свидания / для компании», жалобы и модерация;
- **свои короткие ссылки** — только на адреса нашего сайта;
- **«Нашли ошибку?»** — сообщения о закрывшихся местах и неверных адресах.

Сайт остаётся статическим (GitHub Pages). Пока в `config.js → api.url` пусто, все эти функции выключены и сайт работает как раньше: голоса живут в ссылках.

Код: `handler.mjs` — обработчик без фреймворка, `store/` — два хранилища с одинаковым интерфейсом (SQLite и YDB), `server.mjs` — HTTP-сервер для VPS и Docker, `yc/index.js` → `yc/main.mjs` — точка входа для Yandex Cloud Functions, `lib/` — очистка текста и страница модерации. Клиент в браузере — `assets/api.js` (`window.KudaAPI`).

## Что хранится и сколько

| Что | Какие данные | Срок |
|---|---|---|
| Голоса компании | хэш кода приглашения (сам код сервер не видит), имя, выбранные варианты и дни, хэш секрета голосующего, итоги колеса при ничьей (до 10) | 90 дней после последнего изменения |
| Приглашения | хэш кода, хэш секрета создателя, режим, название, сколько устройств открыло, ответ на свидание (место, день, время, еда, записка) | 90 дней после последнего изменения |
| Отзывы | место, оценка, текст (очищенный), теги, имя, «для чего ходили», хэш устройства и хэш Яндекс ID (если вход подтверждён) | пока модератор не удалит: скрытый отзыв на сайте не виден, по просьбе автора его удаляют навсегда (в /admin: «Скрыть», затем «Удалить навсегда») |
| Жалобы на отзывы | хэш устройства и хэш IP (одна жалоба с каждого), причина | пока есть отзыв — удаляются вместе с ним |
| Короткие ссылки | адрес страницы сайта | 180 дней |
| Сообщения об ошибках | место, текст, хэш устройства | до разбора, не больше 365 дней |
| Счётчики лимитов | хэш IP, хэш устройства | до конца окна (10 минут или сутки), «когда устройство пришло впервые» — 30 дней |

Хэши солёные (`HASH_SALT`): по ним нельзя восстановить IP или id устройства. Секреты (`secret`, `ownerSecret`) сервер не хранит — только их SHA-256. В журнал не пишутся ни IP, ни параметры, ни тела запросов. Просроченные записи удаляются автоматически: в Yandex Cloud счётчики и короткие ссылки удаляет сама база (TTL), остальное — таймер раз в сутки; на своём сервере — раз в час.

## Почему в России

Имена в голосах, тексты отзывов и ответы на приглашения — персональные данные. По 152-ФЗ (ч. 5 ст. 18) персональные данные граждан России нужно записывать и хранить в базах, которые находятся в России. Поэтому основной вариант — Yandex Cloud (регион `ru-central1`), запасной — свой сервер в российском дата-центре. Перед запуском оператору нужно подать уведомление в Роскомнадзор и описать хранение в `privacy.html`; детали лучше сверить с юристом.

## Вариант 1. Yandex Cloud (рекомендуем)

Функция Cloud Functions + база YDB Serverless (Document API). Ничего не нужно администрировать, при объёме запуска это бесплатно.

1. Заведи аккаунт и платёжный аккаунт на [console.yandex.cloud](https://console.yandex.cloud), создай каталог (или используй `default`).
2. Установи на компьютер: [yc CLI](https://yandex.cloud/ru/docs/cli/quickstart) (потом `yc init` — выбери облако и каталог), `jq`, `zip`, `curl`, `openssl` и Node.js 22.
   На macOS: `brew install jq` (остальное обычно уже есть); на Ubuntu: `sudo apt install jq zip curl openssl`.
3. Из корня репозитория запусти:

   ```bash
   ALLOWED_ORIGINS="https://<ник>.github.io" \
   SITE_ORIGINS="https://<ник>.github.io/<репозиторий>/" \
   bash server/yc/deploy.sh
   ```

   Если у сайта свой домен — укажи его: `ALLOWED_ORIGINS="https://kuda-idem.ru"`, `SITE_ORIGINS="https://kuda-idem.ru/"`. Можно несколько адресов через пробел.

   Скрипт по шагам:
   - создаёт сервисный аккаунт `kuda-api-sa` с ролями `ydb.editor` и `functions.functionInvoker`;
   - создаёт базу YDB Serverless `kuda-db` и ждёт, пока она запустится;
   - выпускает статический ключ для Document API и кладёт его, пароль модерации и соль в секрет Lockbox `kuda-api-secrets` (функция читает их как переменные окружения, в коде и в настройках функции их нет);
   - создаёт таблицы `kuda_inv`, `kuda_rev`, `kuda_short`, `kuda_lim` и включает TTL для счётчиков лимитов и коротких ссылок (база удаляет их сама; включение может идти до часа — если скрипт об этом предупредил, запусти его ещё раз позже);
   - собирает архив, создаёт публичную функцию `kuda-api` (Node.js 22, 256 МБ, таймаут 10 с) и выкатывает версию;
   - создаёт таймер `kuda-api-cleanup` — раз в сутки (03:00 по Москве) удаляет просроченные данные;
   - проверяет, что API отвечает, и печатает адрес и пароль модерации (пароль — один раз, сохрани его).
4. Впиши адрес в `config.js`:

   ```js
   api: {
     url: 'https://functions.yandexcloud.net/d4e…',
   },
   ```

5. Открой `https://functions.yandexcloud.net/d4e…?admin=1` и введи пароль (`ADMIN_TOKEN`) в форму.

Обновить код — запусти скрипт ещё раз: ресурсы переиспользуются, выкатывается новая версия функции. Новые ключ, пароль и соль — `ROTATE_SECRETS=1 bash server/yc/deploy.sh` (свой пароль — `ADMIN_TOKEN=… ROTATE_SECRETS=1 …`; старые статические ключи сервисного аккаунта скрипт удалит; после смены соли «один отзыв с устройства» начинает считаться заново).

Свой адрес вместо `functions.yandexcloud.net/…` — через API Gateway: создай шлюз с интеграцией `cloud_functions` на эту функцию для путей `/` и `/admin`, подключи домен и сертификат Certificate Manager, впиши адрес шлюза в `config.js`.

Без статического ключа: если в окружении функции нет `AWS_ACCESS_KEY_ID`, она ходит в YDB с IAM-токеном своего сервисного аккаунта (`context.token`). Ключ в Lockbox — основной, проверенный вариант.

Если в журнале функции появляются ошибки `Throttling…` или клиенты получают `busy` — подними лимит RU/с в настройках базы (консоль → YDB → `kuda-db` → «Изменить»).

## Вариант 2. Свой сервер с Docker и SQLite

Подойдёт любой VPS в российском дата-центре (1 vCPU, 512 МБ хватит с запасом).

```bash
git clone <репозиторий> && cd <репозиторий>
docker build -t kuda-api server/
docker run -d --name kuda-api --restart unless-stopped \
  -p 127.0.0.1:8787:8787 -v kuda-data:/data \
  -e ALLOWED_ORIGINS="https://<ник>.github.io" \
  -e SITE_ORIGINS="https://<ник>.github.io/<репозиторий>/" \
  -e ADMIN_TOKEN="$(openssl rand -hex 24)" \
  -e HASH_SALT="$(openssl rand -hex 24)" \
  -e TRUST_PROXY=1 \
  kuda-api
docker inspect kuda-api --format '{{range .Config.Env}}{{println .}}{{end}}' | grep ADMIN_TOKEN   # запиши пароль
```

Сервер слушает только `127.0.0.1:8787`, наружу его отдаёт обратный прокси с HTTPS. Самый простой — Caddy (сертификат получит сам), `/etc/caddy/Caddyfile`:

```
api.kuda-idem.ru {
  reverse_proxy 127.0.0.1:8787
}
```

Caddy записывает адрес клиента в `X-Forwarded-For`, поэтому `TRUST_PROXY=1`: сервер берёт правый адрес из этого заголовка (без прокси не включай — иначе адрес можно подделать). Для nginx: `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` и тоже `TRUST_PROXY=1`; если в nginx настроен только `proxy_set_header X-Real-IP $remote_addr;` — `TRUST_PROXY=x-real-ip`. `X-Real-IP` при `TRUST_PROXY=1` не читается: Caddy пропускает его от клиента как есть, и лимиты можно было бы обойти.

В `config.js` — `api: { url: 'https://api.kuda-idem.ru' }`, модерация — `https://api.kuda-idem.ru/admin`.

База — один файл `/data/kuda.db` в томе `kuda-data`. Резервная копия на ходу:

```bash
docker exec kuda-api node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('/data/kuda.db').exec(\"VACUUM INTO '/data/backup.db'\")"
docker cp kuda-api:/data/backup.db ./kuda-$(date +%F).db
```

Без Docker: Node.js 22.5+, `cd server && npm ci --omit=dev`, затем `npm start` с теми же переменными (удобно через systemd с `Restart=always` и `EnvironmentFile=`).

## Переменные окружения

| Переменная | Что это | По умолчанию |
|---|---|---|
| `ALLOWED_ORIGINS` | Сайты, которым браузер разрешит читать ответы API (CORS), через пробел или запятую. Запросы с других сайтов получают `403 origin` | пусто — только запросы без `Origin` (curl) |
| `SITE_ORIGINS` | Адреса сайта для коротких ссылок: origin или origin + путь (`https://user.github.io/date-invite/`). Сокращаются только ссылки внутри них | пусто — сокращатель выключен |
| `ADMIN_TOKEN` | Пароль страницы модерации, не короче 16 символов | пусто — `/admin` выключена |
| `HASH_SALT` | Соль для хэшей IP, устройств и Яндекс ID | `kuda-v1` (в бою задай свою) |
| `STORE` | `sqlite` или `ydb` | `sqlite` |
| `SQLITE_PATH` | Файл базы SQLite | `./data/kuda.db` |
| `YDB_DOCAPI_ENDPOINT` | Document API endpoint базы YDB (`https://docapi.serverless.yandexcloud.net/ru-central1/…`) | — |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Статический ключ сервисного аккаунта для YDB | — (тогда IAM-токен функции) |
| `YDB_TABLE_PREFIX` | Префикс таблиц YDB | `kuda_` |
| `YDB_REGION` | Регион | `ru-central1` |
| `PORT`, `HOST` | Где слушать (`server.mjs`) | `8787`, `127.0.0.1` (в Docker `0.0.0.0`) |
| `TRUST_PROXY` | `1` — брать адрес клиента из правого `X-Forwarded-For` (Caddy, nginx с `$proxy_add_x_forwarded_for`); `x-real-ip` — из `X-Real-IP` | выключено — адрес соединения |
| `LOG_REQUESTS` | `0` — не писать строку на каждый запрос | пишет |
| `STORE_SKIP_INIT` | `1` — не проверять и не создавать таблицы при старте (в Cloud Functions это делает `deploy.sh`) | проверяет |

## Протокол

Все запросы — на один адрес. `POST` с телом JSON `{action, …}` и `Content-Type: text/plain` (так браузер не делает preflight) или `GET` с параметрами. Ответ — `{ok: true, …}` или `{ok: false, error: 'код'}`. Тело — не больше 8 КБ.

| Запрос | Что делает |
|---|---|
| `POST vote {key, voter: {id, n, y, o, d}, secret, seed?}` | Голос; время ставит сервер. Первый голос с этим `id` запоминает хэш `secret`, дальше менять его можно только с тем же секретом. `seed` — голоса из старой ссылки, добавляются, только если такого `id` ещё нет. До 60 голосующих → `{votes, rev, spin, spins}` |
| `GET ?votes=<key>&rev=<n>` | Итоги `{votes, rev, spin, spins}`; `{same: true}`, если `rev` не изменился |
| `POST spin {key, result: {i, d?, L?}}` | Итог колеса при ничьей: `i` — вариант, `d` — день, `L` — набор лидеров этой ничьей (номера вариантов по возрастанию через запятую, `'0,3,5'`, до 60 символов, `i` среди них). Для каждого `L` остаётся первый итог; голоса поменялись и ничья другая — новый `L`, новый итог. Хранится до 10 наборов на приглашение, самый старый вытесняется. Без `L` (старые клиенты; `result` может быть и просто номером варианта) — один итог на приглашение, как раньше → `{spin, spins, rev}`, где `spin` — итог для этого `L` |
| `POST invite {key, owner, mode, title}` | Создатель регистрирует приглашение (`owner` = хэш его секрета); повтор — можно, чужой — `taken` |
| `POST opened {key, dev}` | Приглашение открыли (один раз на устройство) |
| `POST answer {key, answer}` | Ответ на свидание (последний заменяет прежний) |
| `POST mine {ownerSecret, keys[≤50]}` | «Мои приглашения» — только те, где совпал владелец |
| `GET ?ratings=1` | `{r: {место: [средняя, сколько, для свидания, для компании, сколько «для свидания», сколько «для компании»]}, at}`; кэш 5 минут |
| `GET ?reviews=<место>&before=<id>&limit=10` | Отзывы, новые сверху |
| `POST review {place, stars, text, tags, name, fit, dev, yandexToken?}` | Отзыв; один на место с устройства (и с Яндекс ID, если токен подтвердился через login.yandex.ru) |
| `POST report {id, dev, reason}` | Жалоба; после трёх разных — отзыв скрыт до проверки |
| `POST short {url}` / `GET ?s=<код>` | Короткая ссылка / раскрыть |
| `POST fix {place, text, dev}` | Сообщение об ошибке в каталоге |
| `GET /admin` или `?admin=1` | Страница модерации: вход формой с паролем `ADMIN_TOKEN` |

В ответах на `vote` и `GET ?votes` `spin` — последний записанный итог колеса (`{i, d, t}` и `L`, если он есть; `null` — колесо ещё не крутили), `spins` — все итоги по наборам лидеров: `{'0,3,5': {i, d, t, L}, …}` (итог старого клиента без `L` туда не входит). Клиент берёт `spins[L]` для текущей ничьей; старые клиенты читают только `spin`.

Коды ошибок: `rate` (лимит, 429), `owner` (чужой голос, 403), `full` (60 голосующих), `taken`, `dup` (уже есть отзыв), `nf` (не найдено), `origin` (сайт не в списке), `big` (тело больше 8 КБ), `busy` (хранилище перегружено, 503), `off` (сокращатель выключен), а также имя неверного поля: `key`, `voter`, `secret`, `stars`, `text`, `tags`, `url`…

## Модерация

Отзыв публикуется сразу, если с ним всё в порядке. На проверку уходят отзывы:

- со ссылками, почтой, @никами или телефонами (они вырезаются из текста);
- с очень коротким текстом (меньше 8 символов), написанные капсом, с несколькими матерными словами (мат маскируется всегда: «б****»);
- пришедшие волной: больше 5 отзывов на одно место за 10 минут, больше 10 отзывов с новых устройств за 10 минут по всему сайту или третий и следующие отзывы на одно место с одного IP за сутки;
- собравшие три жалобы (с одного устройства и с одного IP считается одна).

На странице `/admin`: очередь на проверку (опубликовать / скрыть), сообщения об ошибках в каталоге, последние отзывы (скрыть, ответить от имени сайта), счётчики, пересчёт рейтингов и ручная очистка.

Вход — формой с паролем `ADMIN_TOKEN`. Basic-авторизацию и cookies не используем: в Yandex Cloud Functions заголовки `Authorization` и `Cookie` до функции не доходят. После входа сессия (подпись от `ADMIN_TOKEN`, 12 часов) живёт только в скрытом поле форм — в адресе её нет, все переходы по странице — кнопки («Обновить», «Выйти»). Эта же подпись защищает формы от подделки с чужих сайтов (CSRF). Страница без скриптов, с CSP. Больше 10 попыток входа за 10 минут с одного адреса — вход с него закрыт на 10 минут, даже с верным паролем.

## Защита от злоупотреблений

- Каждое поле проверяется: тип, длина, допустимые значения; лишние поля в ответе на свидание отбрасываются.
- Лимиты по IP, устройству, приглашению и общие хранятся в базе со сроком жизни (новый экземпляр функции их видит), плюс быстрый отсев в памяти.
- CORS — только сайты из `ALLOWED_ORIGINS`; запросы с чужих сайтов отклоняются и на сервере.
- Секреты сравниваются за постоянное время; в ответах и журналах их нет.
- Короткие ссылки — только на адреса из `SITE_ORIGINS` (с проверкой пути), без логина/пароля в адресе.
- Текст отзывов: убираются теги, управляющие и невидимые символы (в том числе символы смены направления и «пустые» буквы), ссылки, почта, @ники и телефоны, лишние пробелы и повторы, мат маскируется.

## Сколько стоит

По тарифам Yandex Cloud на момент написания каждый месяц бесплатно: 1 млн вызовов функций и 10 ГБ×час их работы, 1 млн RU и 1 ГБ данных в YDB Serverless. Опрос итогов голосования стоит около 3 RU, голос — около 15 RU, так что сотни компаний и тысячи отзывов в месяц укладываются в бесплатный объём: **≈ 0 ₽ на запуске**. Сверх него — порядка десятков рублей за миллион запросов. Lockbox — несколько рублей в месяц за секрет. Свой VPS — от ~200 ₽ в месяц.

## Разработка

```bash
cd server
npm install
npm test                       # все тесты: оба хранилища, HTTP, Cloud Functions, клиент assets/api.js
STORE=sqlite SQLITE_PATH=./data/dev.db ALLOWED_ORIGINS=http://localhost:8765 SITE_ORIGINS=http://localhost:8765 ADMIN_TOKEN=dev-admin-token-123 npm start
```

Потом в `config.js` временно: `api: { url: 'http://localhost:8787' }` (http разрешён только для localhost).

Тесты на YDB идут против поддельного Document API в памяти (`test/fake-dynamo.mjs`), который разбирает те же выражения условий и обновлений, что и настоящий.
