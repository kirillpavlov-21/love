# Посредник для Telegram (Google Apps Script)

Необязательная часть сайта. Голоса, ответы на свидания, статусы приглашений и отзывы хранит основной бэкенд (`server/`, настраивается в `config.js → api`). Посредник нужен для двух вещей:

- **уведомления в Telegram** — ответы на приглашения приходят создателю в бота;
- **свои короткие ссылки** — `…/go.html#s=<код>` вместо километровых адресов.

Если посредник не развёрнут (`config.js → telegram.relayUrl` пустой), сайт работает без него: ответ уходит ссылкой-билетом, ссылки сокращает свой сервер (если настроен `config.js → api.url`) или clck.ru.

Сайт публичный, поэтому токен бота на нём хранить нельзя. Ответы на приглашения уходят посреднику — скрипту Google Apps Script, — а он пересылает их в Telegram. Бот общий для всех пользователей сайта: каждый получает у бота **личный ключ владельца**, вставляет его в конструкторе, и ответы на его приглашения приходят ему в личку (или в группу, где он запросил ключ).

Единственный секрет — токен бота. Он хранится только в скрипте, в Google-аккаунте того, кто развернул посредника. Личных chat_id в коде нет.

## Как это работает

```
пользователь → бот: /start                  бот → пользователь: ключ владельца
конструктор → посредник: register + s        id приглашений привязываются к чату владельца вместе с отпечатком c = SHA-256(s)
игра → посредник: text + id + c              посредник → Telegram: сообщение в этот чат, если c совпал
```

**Секрет создателя.** Конструктор хранит в браузере случайную строку `s` (`kuda-creator`). В ссылку-приглашение попадает только её отпечаток `c` (12 символов SHA-256), а сам `s` видит лишь посредник при регистрации. Поэтому тот, у кого есть ссылка, знает `c`, но не может зарегистрировать приглашение на себя так, чтобы ответы гостей уходили ему: у него будет другой отпечаток.

**Приглашение привязано к чату, а не к ключу.** После `/newkey` ответы на уже отправленные приглашения продолжают приходить, перерегистрировать ничего не нужно. После `/stop` ответы не пересылаются, но приглашения остаются за чатом — их нельзя перехватить. Если запись истекла (90 дней без ответов и продлений) и кто-то занял её id, ответы гостей ему всё равно не уйдут: отпечаток не совпадёт. Конструктор раз в день сам продлевает записи из своей истории.

Апдейты от Telegram скрипт забирает сам (`getUpdates`) по триггеру раз в минуту. Вебхук не используется: Apps Script отвечает Telegram редиректом 302, и Telegram такие ответы не принимает. Поэтому бот отвечает на команды с задержкой до минуты.

## Развернуть с нуля

Лучше заведи для посредника отдельный Google-аккаунт: квота на внешние запросы (`UrlFetch`) общая для всех скриптов аккаунта, а посредник рассчитывает, что она вся его.

1. **Бот.** В Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя и ник (должен заканчиваться на `bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. **Скрипт.** Открой https://script.google.com → **Новый проект** → вставь в редактор содержимое `Code.gs`.
3. **Манифест.** **Настройки проекта (⚙️)** → включи «Показывать файл манифеста appsscript.json» → замени его содержимым `appsscript.json` отсюда.
4. **Свойства скрипта.** Там же, в **Настройках проекта** → **Свойства скрипта** → **Добавить свойство**:
   - `TG_TOKEN` — токен от BotFather (обязательно). Можно вписать токен в константу `TG_TOKEN` в начале `Code.gs`, но в свойствах надёжнее: код можно показывать, не боясь утечки.
   - `SITE_URL` — адрес сайта (очень желательно): корень домена (`https://example.ru`), папка (`https://kirillpavlov-21.github.io/love/`) или адрес страницы (`…/love/create.html` — посредник возьмёт папку). Бот добавит его к своим ответам; сокращать можно будет только ссылки сайта и Яндекс Карт, а в ответах гостей нажимаемыми останутся только ссылки на сайт. Без `SITE_URL` все ссылки в ответах обезвреживаются, а сокращать можно любые https-адреса.
   - `ADMIN_CHAT` — chat_id, куда пересылать сообщения об ошибках в каталоге (необязательно, см. ниже).
   - `SHORT_ALLOW` — свои префиксы для сокращателя через запятую, например `https://example.ru/,https://yandex.ru/maps/` (необязательно; заменяет правило «сайт + Яндекс Карты»). Префикс без пути (`https://example.ru`) считается как `https://example.ru/`.
   - `URLFETCH_DAY` — суточная квота UrlFetch, если аккаунт Google Workspace: `100000` (необязательно; по умолчанию 20 000).
5. **Триггеры.** Выбери функцию `setupTriggers` → **▶ Выполнить** → разреши доступ. Появится «Google не проверил это приложение»: жми «Дополнительно» → «Перейти в проект» — это твой собственный скрипт. Функция проверит токен, удалит вебхук, задаст боту описание и меню команд, поставит триггеры (`pollBot` раз в минуту, `cleanup` раз в сутки в 4 утра) и напишет в журнал ник бота.
6. **Веб-приложение.** **Начать развёртывание → Новое развёртывание** → тип «Веб-приложение», «Запуск от имени: я», «Доступ: все» → **Развернуть**. Скопируй адрес вида `https://script.google.com/macros/s/…/exec`.
7. **Сайт.** В `config.js`:
   ```js
   telegram: {
     relayUrl: 'https://script.google.com/macros/s/…/exec',  // адрес из шага 6
     bot: 'имя_бота',                                         // ник бота без @ (из журнала шага 5)
     …
   },
   ```
8. **Проверка.** Напиши боту `/start` → через минуту придёт ключ → вставь его в конструкторе в поле «Ключ владельца» → «Отправить тестовое сообщение». Открой в браузере `<адрес из шага 6>` — ответ `{"ok":true,"bot":"имя_бота"}`.

Настройки (`SITE_URL`, `SHORT_ALLOW`, `URLFETCH_DAY`, `ADMIN_CHAT`) посредник читает раз в 10 минут: поменял свойство — подожди 10 минут или выполни `setupTriggers`.

## Обновить старую версию

Замени код в том же проекте на новый `Code.gs` и манифест → проверь, что токен лежит в свойстве `TG_TOKEN` → выполни `setupTriggers` → **Развернуть → Управление развёртываниями → ✏️ → Версия: новая → Развернуть**. Адрес посредника не меняется, `relayUrl` трогать не нужно.

- Старые записи переходят сами: ключи старого формата получают отметку о дне использования при первом `cleanup`, приглашения старого формата (`ключ|день`, без отпечатка) работают, пока жив их ключ.
- Короткие ссылки, выданные раньше, продолжают раскрываться — и те, у которых таблица превратила хвост кода в число (`0123` → `123`). Лишние пустые столбцы таблицы удалит первый `cleanup`.
- Старый общий `OWNER_KEY` больше не работает. Получи личный ключ у бота (`/start`) и вставь его в конструкторе.

## Короткие ссылки

Сайт не отправляет в чаты километровые ссылки: перед отправкой он просит сократить ссылку (`{"action": "short", "url": "…"}` → `{"ok": true, "id": "1aB3x"}`) и отдаёт людям адрес `…/go.html#s=1aB3x`. Страница `go.html` раскрывает код запросом `GET <relayUrl>?s=1aB3x` и перенаправляет — только на сам сайт или в Яндекс Карты.

- Порядок на сайте: сначала свой сервер (`config.js → api.url`, если настроен), потом посредник, потом clck.ru; если никто не ответил — уходит полная ссылка. `go.html` раскрывает код так же: сначала у сервера, потом у посредника — поэтому коды, выданные посредником раньше, продолжают работать и после подключения сервера.
- Ссылки хранятся в Google-таблице «Короткие ссылки сайта» (создаётся сама при первом сокращении, в твоём Google Диске; в ней 3 столбца — так в лимит Google в 10 млн ячеек влезает больше ссылок). Код — сквозной номер строки в base62 и 4 случайных символа, всего от 5 до 14 знаков: раскрытие быстрое, а коды не перебрать подряд.
- Сокращать можно только адреса сайта и Яндекс Карт (свойства `SITE_URL` или `SHORT_ALLOW`).
- **Не сортируй таблицу и не удаляй в ней строки вручную**: код — это номер строки, и после перестановки выданные ссылки перестанут открываться.
- **Срок хранения — 90 дней.** `cleanup` раз в сутки удаляет строки старше, ссылки на них отвечают `{"ok": false}`. Номера остальных кодов не сдвигаются: свойство `short_off` помнит, сколько строк удалено. Если в кэше остались сведения со старым сдвигом (раскрытие совпало по времени с чисткой), посредник замечает это на первой же неудачной попытке и перечитывает их.
- Если Google временно не открыл таблицу, посредник повторяет попытку и отвечает `busy` — новую таблицу он не создаёт (иначе все выданные ссылки сломались бы). Если таблицу удалили насовсем, удали свойства `short_sheet` и `short_off` — при следующем сокращении появится новая.
- Неудачные раскрытия считаются по каждой строке: больше 20 за 10 минут — перебор хвостов этой строки получает `rate`, остальные ссылки работают. Настоящая ссылка этой строки при этом продолжает открываться (посредник кладёт её в кэш при первой же неудачной попытке), так что чужой перебор не выключает чью-то ссылку. Код с номером за концом таблицы отбрасывается, не открывая её.

После обновления кода нужен доступ к таблицам: выполни любую функцию (например, `stats`) и разреши доступ ещё раз, затем выпусти новую версию развёртывания.

## Сообщения об ошибках в каталоге

В карточках мест и планов есть ссылка «Место закрылось или есть ошибка? Сообщи нам» (у плана — «План устарел или есть ошибка? Сообщи нам»). Если настроен свой сервер (`config.js → api.url`), это форма прямо в карточке и бот не нужен. Без сервера, если в `config.js` → `support.telegram` указан ник этого бота, ссылка открывает бота с параметром `fix_<id>`: бот попросит описать проблему и перешлёт текст в чат из свойства скрипта `ADMIN_CHAT` (chat_id твоего личного чата или рабочей группы; узнать его можно у @userinfobot). Ссылки в тексте и в имени автора обезвреживаются так же, как в ответах гостей; ник автора остаётся, чтобы ему можно было ответить. Если `ADMIN_CHAT` не задан, сообщение попадает только в журнал скрипта (**Выполнения** в редакторе Apps Script) — лучше задай его.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/key` | Показать ключ владельца (если ключа ещё нет — выпустить) |
| `/newkey` | Выпустить новый ключ, старый сразу перестаёт работать |
| `/stop` | Удалить ключ: ответы больше не приходят |

В группе команды пишутся с ником бота: `/key@имя_бота`. Тогда ключ привязывается к группе, и ответы приходят всем её участникам. **`/newkey` и `/stop` в группе выполняются только для создателя и админов группы** (в том числе анонимных) — иначе любой участник мог бы выключить ответы всем. Если группа стала супергруппой, ключ и приглашения переносятся сами.

## Протокол (сайт → посредник)

Запросы — `POST` с JSON в теле (`text/plain`, чтобы браузер не делал preflight). Ответ — `{"ok": true|false, …}`.

| Тело | Что делает |
|---|---|
| `{"action": "test", "key": "…"}` | Тестовое сообщение в чат владельца ключа |
| `{"action": "register", "key": "…", "s": "…", "ids": ["abc123", …]}` | Привязать id приглашений к чату владельца ключа (до 50 за раз) вместе с отпечатком `c = SHA-256("kuda-tg\|" + s)`, первые 12 символов base64url. Приглашение с другим отпечатком не перехватывается (`taken` в ответе). Пустой `ids` — только проверка ключа. Ответ: `{"ok": true, "taken": 0, "fresh": 1}` |
| `{"action": "short", "url": "https://…"}` | Короткий код: `{"ok": true, "id": "1aB3x"}` |
| `{"id": "abc123", "c": "…", "text": "…"}` | Ответ на приглашение: уходит в чат, к которому привязано приглашение, если `c` совпал и у чата есть действующий ключ |

`GET <адрес>?s=<код>` → `{"ok": true, "url": "…"}` или `{"ok": false}`; `GET` без параметров → `{"ok": true, "bot": "имя_бота"}`.

Ошибки — в поле `error`:

| Код | Когда |
|---|---|
| `key` | ключ не подошёл (неверный, заменён через `/newkey`, удалён через `/stop` или по сроку) |
| `secret` | нет секрета создателя `s` (register) |
| `url` | этот адрес сокращать нельзя (short) |
| `rate` | сработал лимит — повтори позже (для `?s=` — слишком много неудачных попыток по этой строке) |
| `busy` | посредник занят, таблица ссылок не открылась или исчерпан запас запросов к Telegram на эти 6 часов — повтори позже |
| `storage` | хранилище переполнено (register) |

**Текст ответа.** Из разметки остаётся только `<b>`, всё остальное экранируется. Посредник раскрывает сущности (`&lt;` и др.) и убирает невидимые символы (склейка эмодзи вроде 🧖‍♀️ остаётся). Потом во всём тексте сразу — так что не помогает и ссылка, разрезанная тегом `<b>`, — обезвреживает всё, из чего Telegram сам сделал бы ссылку, упоминание или команду:

- точка перед буквой или цифрой → «․» (выглядит так же, но Telegram не видит адреса), на всякий случай и «китайские» точки `。．｡` (некоторые программы считают их точкой);
- `://` любой схемы (`https`, `tg`, `ton`…) → `∶//`;
- `@ник` → `＠ник`, `/команда` после пробела или знака препинания → `∕команда`.

Нажимаемыми остаются только ссылки на сайт из `SITE_URL`, и только до первого символа, которого обычно нет в адресах сайта (`«`, `"`, `'`, `<`, скобки и т. п.): на `«`, `»`, `"`, `<`, `>` Telegram обрывает ссылку, и то, что дальше, само стало бы ссылкой, — поэтому дальше идёт обычное обезвреживание. В конце текст обрезается до 3 800 видимых символов (эмодзи не разрезаются) и экранируется заново. От имени бота не получится прислать фишинговую ссылку или кнопку `/stop`.

## Сменить токен (если бот скомпрометирован)

@BotFather → `/revoke` → новый токен → замени свойство `TG_TOKEN`. Если токен хранится в свойстве, больше ничего делать не нужно. Если в константе — выпусти новую версию развёртывания (**Управление развёртываниями → ✏️ → Версия: новая**). Адрес посредника не меняется, ключи пользователей продолжают работать.

## Защита и ограничения

- Пересылаются только ответы на приглашения, которые зарегистрировал их создатель (совпал отпечаток секрета) и у чата которых есть действующий ключ. Чужие приглашения и спам отбрасываются.
- Через адрес посредника нельзя ничего прочитать или узнать токен и чужие ключи.
- **Лимиты за 10 минут** (константа `LIM` в начале `Code.gs`). IP-адреса Apps Script не видит, поэтому лимиты — по ключу, чату, приглашению, «семейству» ссылок и строке таблицы:
  - уведомления: 20 по одному приглашению, 40 одному владельцу, 250 всего; если общий поток кто-то выел, у каждого владельца первые 5 сообщений проходят из отдельного запаса (100 на всех);
  - тест: 5 на ключ; новые приглашения: 100 на чат и 1 500 всего; новые ключи: 5 на чат и 60 всего;
  - короткие ссылки — свой поток, отдельный от уведомлений: 30 для одного приглашения (всё до первого `&` в адресе) и 300 всего; неудачные раскрытия — 20 на строку таблицы;
  - бот: не больше 12 ответов одному чату (из них 3 подсказки на обычные сообщения) и 300 всего; сообщения об ошибках в каталоге — 3 от чата и 60 всего. Лишнее бот молча пропускает — и команды сверх лимита даже не читают хранилище, так что поток `/key` от одного человека не выест квоту свойств.
- **Счётчики лимитов** живут в кэше Apps Script (около 1 000 записей). Общие счётчики хранятся так, что кэш выбрасывает их последними, поэтому общие лимиты не сбрасываются даже под нагрузкой. Счётчики «на кого-то» при сильной нагрузке могут потеряться — тогда суточную квоту всё равно держит счётчик запросов к Telegram с копией в свойствах.
- **Квота запросов к Telegram (UrlFetch)** — 20 000 в сутки на бесплатном аккаунте, когда Google её обнуляет, заранее не известно. Поэтому посредник считает запросы по 6-часовым четвертям и тратит на четверть не больше 19 % квоты (любые сутки задевают не больше пяти четвертей — в сумме не больше 95 %): 3 800 запросов. Из них 400 всегда остаются опросу Telegram (бот продолжает получать команды), ещё 510 — первым 5 сообщениям каждого владельца за 10 минут (спам с десятков своих ключей не оставит без ответов остальных); на всё прочее — 2 890. Когда запас кончился, уведомления отвечают `busy`, бот молчит до следующей четверти.
- **Хранилище.** Свойства скрипта ограничены 500 КБ. На один чат — не больше 100 приглашений (старые вытесняются). Когда занято больше 420 КБ, посредник сам удаляет самые старые приглашения всех пользователей, пока не останется 340 КБ, — регистрация не падает и посредник не перестаёт работать у всех. `cleanup` раз в сутки удаляет приглашения старше 90 дней, ключи без приглашений, которыми не пользовались 180 дней (такому пользователю бот выдаст новый ключ по `/key`), и записи-сироты, пересобирает списки и записывает всё одним вызовом. Сколько занято, покажет функция `stats` (▶ Выполнить → журнал).
- **Квоты Google.** Чтений и записей свойств — 50 000 в сутки: на одно уведомление уходит около 4 чтений, настройки читаются раз в 10 минут. Триггеры могут работать 90 минут в сутки, опрос раз в минуту тратит из них примерно 20–30 минут. Одновременно выполняется не больше 30 запросов: все посетители сайта делят этот лимит.
- **Что хранится.** В свойствах — chat_id, ключ и день, когда им последний раз пользовались, id приглашений (хэши ссылок) и отпечатки секретов. Тексты ответов в свойствах не сохраняются. Таблица коротких ссылок хранит полный адрес — если сокращают ссылку-билет, в нём есть ответ гостя (место, день, P.S.); такие строки удаляются через 90 дней. Всё хранится в Google-аккаунте владельца скрипта, то есть за пределами России.
- id приглашения — 32-битный хэш ссылки, поэтому изредка у двух разных приглашений он совпадает. Тогда ответы на второе приглашение не придут в Telegram, но ссылка-билет у человека всё равно останется.
- **От целенаправленной атаки потоком запросов посредник не защищён.** Apps Script не видит IP-адресов: тот, кто непрерывно шлёт запросы со случайными id или ключами, займёт 30 одновременных выполнений и может до конца суток выесть квоту чтений свойств — тогда уведомления и бот замолчат до следующего дня. Сайт при этом работает: ответы уходят ссылкой-билетом, ссылки сокращает свой сервер или clck.ru. Если такое случилось, временно очисти `telegram.relayUrl` в `config.js` или выпусти новое развёртывание с другим адресом.

## Проверка без Google

`relay/test/harness.mjs` загружает `Code.gs` в Node с поддельными сервисами Apps Script (свойства, кэш, замок, таблицы, UrlFetch) и прогоняет основные сценарии: ключи и команды бота (в том числе поток команд и права в группах), регистрацию и уведомления, обезвреживание текста (известные обходы), короткие ссылки (перебор хвостов, сдвиг после чистки), лимиты, квоту UrlFetch, чистку. Поддельные сервисы повторяют документированное поведение Google, поэтому после выкладки всё равно сделай проверку из шага 8.

```
node relay/test/harness.mjs
```
