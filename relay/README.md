# Посредник для Telegram (Google Apps Script)

Сайт публичный, поэтому токен бота на нём хранить нельзя. Ответы на приглашения уходят посреднику — скрипту Google Apps Script, — а он пересылает их в Telegram. Бот общий для всех пользователей сайта: каждый получает у бота **личный ключ владельца**, вставляет его в конструкторе, и ответы на его приглашения приходят ему в личку (или в группу, где он запросил ключ).

Единственный секрет — токен бота. Он хранится только в скрипте, в Google-аккаунте того, кто развернул посредника. Личных chat_id в коде нет.

## Как это работает

```
пользователь → бот: /start           бот → пользователь: ключ владельца
конструктор → посредник: register     id приглашений привязываются к ключу
игра → посредник: text + id           посредник → Telegram: сообщение в чат владельца ключа
```

Апдейты от Telegram скрипт забирает сам (`getUpdates`) по триггеру раз в минуту. Вебхук не используется: Apps Script отвечает Telegram редиректом 302, и Telegram такие ответы не принимает. Поэтому бот отвечает на команды с задержкой до минуты.

## Развернуть с нуля

1. **Бот.** В Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя и ник (должен заканчиваться на `bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. **Скрипт.** Открой https://script.google.com → **Новый проект** → вставь в редактор содержимое `Code.gs`.
3. **Манифест.** **Настройки проекта (⚙️)** → включи «Показывать файл манифеста appsscript.json» → замени его содержимым `appsscript.json` отсюда.
4. **Токен.** Там же, в **Настройках проекта** → **Свойства скрипта** → **Добавить свойство**: имя `TG_TOKEN`, значение — токен от BotFather. (Можно вписать токен в константу `TG_TOKEN` в начале `Code.gs`, но в свойствах надёжнее: код можно показывать, не боясь утечки.)
   Необязательно: свойство `SITE_URL` — адрес конструктора, например `https://example.ru/create.html`. Бот будет добавлять его к своим ответам.
5. **Триггеры.** Выбери функцию `setupTriggers` → **▶ Выполнить** → разреши доступ. Появится «Google не проверил это приложение»: жми «Дополнительно» → «Перейти в проект» — это твой собственный скрипт. Функция проверит токен, удалит вебхук, задаст боту описание и меню команд, поставит триггеры (`pollBot` раз в минуту, `cleanup` раз в сутки) и напишет в журнал ник бота.
6. **Веб-приложение.** **Начать развёртывание → Новое развёртывание** → тип «Веб-приложение», «Запуск от имени: я», «Доступ: все» → **Развернуть**. Скопируй адрес вида `https://script.google.com/macros/s/…/exec`.
7. **Сайт.** В `config.js`:
   ```js
   telegram: {
     relayUrl: 'https://script.google.com/macros/s/…/exec',  // адрес из шага 6
     bot: 'имя_бота',                                         // ник бота без @ (из журнала шага 5)
     …
   },
   ```
8. **Проверка.** Напиши боту `/start` → через минуту придёт ключ → вставь его в конструкторе в поле «Ключ владельца» → «Отправить тестовое сообщение».

## Обновить старую версию (с одним владельцем)

Замени код в том же проекте на новый `Code.gs` и манифест → перенеси токен в свойство `TG_TOKEN` → выполни `setupTriggers` → **Развернуть → Управление развёртываниями → ✏️ → Версия: новая → Развернуть**. Адрес посредника не меняется, `relayUrl` трогать не нужно.

Старый общий `OWNER_KEY` больше не работает. Получи личный ключ у бота (`/start`) и вставь его в конструкторе — приглашения из истории этого браузера подключатся заново автоматически. Старые записи приглашений удалит `cleanup`.

## Короткие ссылки

Сайт не отправляет в чаты километровые ссылки: перед отправкой он просит посредника сократить ссылку (`{"action": "short", "url": "…"}` → `{"ok": true, "id": "Ab3"}`) и отдаёт людям адрес `…/go.html#s=Ab3`. Страница `go.html` раскрывает код запросом `GET <relayUrl>?s=Ab3` и перенаправляет — только на сам сайт или в Яндекс Карты.

- Ссылки хранятся в Google-таблице «Короткие ссылки сайта» (создаётся сама при первом сокращении, в твоём Google Диске). Код — номер строки в base62, поэтому раскрытие мгновенное и место не кончается.
- Сокращать можно только адреса сайта и Яндекс Карт: свойство `SITE_URL` (адрес сайта) или `SHORT_ALLOW` (свои префиксы через запятую).
- Если посредник не настроен, сайт пробует clck.ru и is.gd, а если и они недоступны — отправляет полную ссылку.

После обновления кода нужен доступ к таблицам: выполни любую функцию (например, `stats`) и разреши доступ ещё раз, затем выпусти новую версию развёртывания.

## Сообщения об ошибках в каталоге

В карточках мест и планов есть ссылка «Нашли ошибку или место закрылось?». Если в `config.js` → `support.telegram` указан ник этого бота, ссылка открывает бота с параметром `fix_<id>`: бот попросит описать проблему и перешлёт текст в чат из свойства скрипта `ADMIN_CHAT` (chat_id твоего личного чата или рабочей группы; узнать его можно у @userinfobot).

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/key` | Показать ключ владельца (если ключа ещё нет — выпустить) |
| `/newkey` | Выпустить новый ключ, старый сразу перестаёт работать |
| `/stop` | Удалить ключ: ответы больше не приходят |

В группе команды пишутся с ником бота: `/key@имя_бота`. Тогда ключ привязывается к группе, и ответы приходят всем её участникам. Если группа стала супергруппой, ключ переносится сам.

## Протокол (сайт → посредник)

Все запросы — `POST` с JSON в теле (`text/plain`, чтобы браузер не делал preflight). Ответ — `{"ok": true|false}`.

| Тело | Что делает |
|---|---|
| `{"action": "test", "key": "…"}` | Тестовое сообщение в чат владельца ключа |
| `{"action": "register", "key": "…", "ids": ["abc123", …]}` | Привязать id приглашений к ключу (до 50 за раз). Приглашение, уже привязанное к действующему ключу другого человека, не перехватывается (`taken` в ответе) |
| `{"id": "abc123", "text": "…"}` | Ответ на приглашение: уходит в чат владельца, если приглашение зарегистрировано действующим ключом |

`GET` на адрес посредника возвращает `{"ok": true, "bot": "имя_бота"}`.

## Сменить токен (если бот скомпрометирован)

@BotFather → `/revoke` → новый токен → замени свойство `TG_TOKEN`. Если токен хранится в свойстве, больше ничего делать не нужно. Если в константе — выпусти новую версию развёртывания (**Управление развёртываниями → ✏️ → Версия: новая**). Адрес посредника не меняется, ключи пользователей продолжают работать.

## Защита и ограничения

- Пересылаются только ответы на приглашения, которые конструктор зарегистрировал действующим ключом. Чужие приглашения и спам отбрасываются.
- Через адрес посредника нельзя ничего прочитать или узнать токен и чужие ключи.
- Не больше 40 сообщений одному владельцу и 300 сообщений всего за 10 минут. Не больше 100 новых приглашений на владельца за 10 минут.
- Хранятся только chat_id, ключ и id приглашений (хэши ссылок). Тексты ответов не сохраняются.
- **Хранилище.** Свойства скрипта ограничены 500 КБ. Этого хватает примерно на 2 000 пользователей и 9 000 приглашений одновременно. `cleanup` раз в сутки удаляет приглашения старше 90 дней и приглашения с отключёнными ключами. Сколько занято, покажет функция `stats` (▶ Выполнить → журнал). Если места начнёт не хватать, данные нужно перенести в базу.
- **Квоты Google.** На бесплатном аккаунте триггеры могут работать 90 минут в сутки. Опрос раз в минуту тратит из них примерно 20–30 минут. Запросов к внешним адресам (`UrlFetch`) — 20 000 в сутки, из них около 1 500 уходит на опрос.
- id приглашения — 32-битный хэш ссылки, поэтому изредка у двух разных приглашений он совпадает. Тогда ответы на второе приглашение не придут в Telegram, но ссылка-билет у человека всё равно останется.
