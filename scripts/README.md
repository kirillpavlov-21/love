# scripts/ — SEO-страницы «Куда идём?»

`build-seo.mjs` собирает статические подборки по городам, `sitemap.xml` и `robots.txt`. Нужен только Node 22, без зависимостей и без сети.

| Город     | Папка     | Адрес                   | Ссылки в приложение                               |
|-----------|-----------|-------------------------|---------------------------------------------------|
| Москва    | `moskva/` | `/moskva/<подборка>/`   | как раньше (`start.html?place=…&m=…`)             |
| Петербург | `spb/`    | `/spb/<подборка>/`      | с `&city=spb` (`start.html?place=spb-…&m=…&city=spb`) |

## Запуск

```sh
node scripts/build-seo.mjs                    # пересобрать moskva/, spb/, sitemap.xml и robots.txt
node scripts/build-seo.mjs --dry              # только отчёт: что появится, изменится и удалится
node scripts/build-seo.mjs --date=2026-10-31  # собрать так, будто сегодня другой день (проверить афишу)
node scripts/build-seo.mjs --out=/tmp/seo     # записать всё в другую папку и посмотреть, не трогая сайт
```

Пересобирать нужно после каждого обновления данных: `assets/places.js`, `places-spb.js`, `events.js`, `events-spb.js`, `sport.js`, `auto.js` и `photos.js`. Афиша и «Сегодня» зависят от дня сборки, поэтому без новых данных пересобирать тоже полезно — лучше каждый день. После сборки закоммить `moskva/`, `spb/`, `sitemap.xml` и `robots.txt`.

## Как делится по городам

- Город места, плана и события определяется так же, как на сайте (`DateKit.cityOf`). Сначала смотрим поле `city`, потом префикс id (`spb-`, `ev-spb-`), потом координаты.
- План относится к городу своих точек. План с точками в двух городах не попадает никуда, а в отчёте появляется предупреждение.
- Футбольные матчи берутся из `sport.js`, у каждого матча свой `city`. Они попадают на страницу `futbol/` своего города и в общие подборки афиши («Сегодня», «Выходные» и другие).
- Станции метро берутся из `assets/geo.js`: таблица `FIXED` для Москвы и `FIXED_SPB` для Петербурга. Названия станций совпадают («Маяковская», «Спортивная»…), поэтому у каждого города свои страницы «у метро».
- Районы Петербурга — это коды `okr` из `DateKit.CITIES.spb.okrs` (`center`, `petrograd`, `vo`, `north`, `nw`, `south`, `sw`, `east`, `out`). Их же понимает `?okr=` на главной.
- Москва собирается всегда. Петербург собирается, только когда в каталоге есть его места; без мест папка `spb/` не создаётся, а если была — удаляется.
- Когда собраны оба города, в подвале каждой подборки есть ссылка на подборки другого города.

## Что проверяет скрипт

Скрипт падает, если в тексте страницы встретилось упоминание Telegram или Instagram, `undefined`/`NaN` или если JSON-LD не разбирается.

Свои файлы он перечисляет в `<город>/.generated.json` и удаляет устаревшие страницы. Если манифест потерян, свои страницы скрипт узнаёт по `<meta name="generator">`. Руками в `moskva/` и `spb/` ничего не правь: следующий запуск перепишет.

Картинка превью для Петербурга — `assets/og-spb.png`, если она есть. Пока её нет, используется нейтральная `og-invite.png`: на `og-hub.png` написано «в Москве».
