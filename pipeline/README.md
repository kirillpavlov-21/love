# Конвейер каталога «Куда идём?»

Каждое утро робот читает Telegram-каналы и Instagram-аккаунты о местах Москвы и Петербурга, а также ваш «ящик» в issues. Он находит новые места, закрытия и события, собирает подборки с новыми местами и присылает всё это **Pull Request'ом**. На сайт ничего не попадает, пока вы не нажмёте Merge.

```
источники ──► модель вытаскивает факты ──► код проверяет ──► assets/auto.js + фото ──► PR с отчётом
 (Telegram,     (своими словами,             (дубли, адрес на карте,                     (вы смотрите
  Instagram,     без имён источников)          метро ≤ 3 км, правила планов,              и мержите)
  issues)                                      лицензия фото)
```

## Что делает

- **Новые места.** Конвейер проверяет, что места ещё нет в каталоге того же города (по названию, адресу и координатам) и что адрес находится на карте этого города: Москвы с ближним Подмосковьем или Петербурга с пригородами и ближней Ленобластью (Мурино, Кудрово, Всеволожск). Ближайшее метро своего города должно быть не дальше 3 км; исключение — пригороды Петербурга (Пушкин, Петергоф, Кронштадт…): такое место берётся без станции, и в отчёте есть пометка вписать ж/д станцию. Затем он определяет округ, раздел каталога, эмодзи и ценовую категорию и пишет описание своими словами (до 180 знаков). Фото берётся только с Wikimedia Commons со свободной лицензией, с автором и лицензией. Место получает пометку `added`, по ней сайт может показать полку «Новые места».
- **Закрытия.** Место закрывается, только если в тексте поста есть слова о закрытии («закрылось», «последний день работы»…) и это место есть в каталоге. Модель должна назвать место, название должно совпасть с каталогом, уверенность — не ниже 0,8. За запуск — не больше 5 закрытий, остальные ждут следующего дня. Закрытое место сайт скрывает везде, и подборки с ним тоже.
- **События.** Это концерты, спектакли, выставки и т. п., у которых дата ещё не прошла и есть официальная https-ссылка. Ссылки на соцсети, мультиссылки (taplink, linktr.ee), сокращатели, IP-адреса и ссылки с именем источника не берутся, метки вроде `utm_source` срезаются. Площадка должна быть в каталоге или находиться на карте. Повтор (те же дни, похожее название, та же площадка) не добавляется, а показывается в отчёте.
- **Подборки.** Для новых мест (до 10 за запуск) модель предлагает планы из соседних мест каталога. Код проверяет каждый план по правилам сайта: до 1600 м между точками, сначала прогулка, потом еда, не два ужина подряд, 18+ по правилам. Планы с нарушениями отбрасываются.
- **Обновления известных мест** (переезд, новые часы) **не применяются**: они только перечислены в отчёте, чтобы вы поправили `assets/places.js` (места Петербурга — `assets/places-spb.js`) руками.
- **Лимиты за один запуск:** в каждом городе не больше 25 мест, 5 закрытий, 30 событий и 15 подборок; модели отдаётся не больше 120 постов на оба города (поровну, если постов больше) и не дольше 35 минут. Что не влезло, переносится на следующий день.
- **Сбои.** Если геокодер или модель недоступны (лимит запросов, ошибка сервиса, нет связи), посты не помечаются прочитанными и разбираются в следующий раз. Если модель не ответила ни разу или недоступны все источники одного вида, запуск в Actions становится красным, и GitHub присылает письмо.

Всё автоматическое лежит в `assets/auto.js`: в начале файла постоянный код слияния, дальше данные. Файл загружается после `places.js`, `places-spb.js`, `events.js`, `events-spb.js` и `sport.js` и только добавляет новое; места из этих файлов он не переписывает. Руками его лучше не править, кроме как в PR (см. ниже).

### Два города

- **Город поста** берётся из списка источников (см. ниже, `cities`), у ящика — из метки issue или из текста. Модель может поправить город, если в посте прямо сказано, что место в другом городе: московский канал иногда пишет про Петербург. Код верит такой поправке, только если город или пригород назван в тексте или в адресе («в Петербурге», «Пушкин, …», «в Химках»); иначе остаётся город источника.
- **Всё остальное — в городе поста:** поиск адреса (рамка Москвы или Петербурга), станции метро (`FIXED` или `FIXED_SPB` из `assets/geo.js`), районы, поиск дублей, соседи для подборок. «Кофемания» в Москве и в Петербурге — разные места; «Маяковская» есть в обоих городах.
- **Районы Петербурга** (`okr`): `center` (Центральный, Адмиралтейский), `petrograd`, `vo`, `north` (Выборгский, Калининский), `nw` (Приморский), `south` (Московский, Фрунзенский), `sw` (Кировский, Красносельский), `east` (Невский, Красногвардейский), `out` (Пушкинский, Петродворцовый, Кронштадтский, Курортный, Колпинский районы и Ленобласть).
- **id в Петербурге:** места `spb-<название>`, подборки `spb-d-auto-…` / `spb-g-auto-…` / `spb-w-auto-…`, события `ev-spb-…`, и у каждой записи поле `city: "spb"`. Московские записи — как раньше, без поля `city`. По префиксу id сайт понимает город, поэтому приглашения с петербургскими местами открываются в Петербурге.
- **Подборка — только из одного города:** план с местами двух городов отклоняется даже с тегом `drive`.

### Правила, которые конвейер соблюдает

- В файлах сайта нет имён каналов и аккаунтов и нет подписей вроде «из канала…». Источники упоминаются только в ветке `pipeline-data`, в отчёте и в описании PR.
- Тексты постов и фото из постов не копируются. Описания пишутся своими словами; описание, в котором пять слов подряд совпадают с постом, отклоняется. Фото берутся только с Wikimedia Commons (CC0, общественное достояние, CC BY, CC BY-SA, Free Art License), с автором и лицензией.
- Факты (название, адрес, часы, даты, цены) брать можно.

## Настройка (один раз)

### 1. Секреты

**Settings → Secrets and variables → Actions → New repository secret:**

| Секрет | Нужен? | Что это |
|---|---|---|
| `ANTHROPIC_API_KEY` | **обязательно** | Ключ API Claude (console.anthropic.com → API Keys). Без него запуск сразу падает с понятной ошибкой. |
| `YANDEX_GEOCODER_KEY` | по желанию | Ключ «HTTP Геокодера» из кабинета разработчика Яндекса. Без него адреса ищутся через OpenStreetMap (Nominatim): это бесплатно, но медленнее (1 запрос в секунду) и иногда промахивается мимо дома. |
| `IG_ACCESS_TOKEN` и `IG_USER_ID` | по желанию | Чтение Instagram, см. ниже. Без них Instagram-аккаунты из списка просто пропускаются. |
| `PIPELINE_SOURCES` | по желанию | Список источников в виде JSON (как `sources.json`). Если задан, он используется вместо файла из ветки `pipeline-data`. Список это **не скрывает**: имена всё равно видны в `state.json`, отчётах и описании PR. |

### 2. Права для Actions

**Settings → Actions → General → Workflow permissions:**

- выберите **Read and write permissions**;
- включите **Allow GitHub Actions to create and approve pull requests**. Без этой галочки робот не сможет открыть PR.

### 3. Первый запуск и список источников

1. Откройте **Actions → «Каталог — автообновление» → Run workflow** и включите `dry`. Робот создаст служебную ветку `pipeline-data` с файлами `sources.json`, `state.json` и папкой `reports/`.
2. Откройте на GitHub ветку `pipeline-data`, файл `sources.json`, и нажмите ✏️:

   ```json
   {
     "telegram": ["имя_канала", "ещё_один"],
     "instagram": ["имя.аккаунта"],
     "cities": {
       "spb": { "telegram": ["канал_про_питер"], "instagram": ["аккаунт.про.питер"] }
     },
     "inbox": true
   }
   ```

   Списки `telegram` и `instagram` верхнего уровня — **Москва** (так было и раньше, старый файл без `cities` работает как прежде). Источники **Петербурга** — в `cities.spb`. Канал, который пишет про оба города, впишите в оба списка: тогда город каждого поста определит модель по тексту. Запись вида `{"handle": "канал", "city": "spb"}` в любом списке тоже понимается (город записи важнее города списка), но основной формат — `cities`. Имена пишутся без `@` и без ссылок (`https://t.me/имя` тоже поймётся). Заглушки с дефисом из примера конвейер пропускает. Ключ `_help` можно удалить.
3. Запустите ещё раз с `dry`. В ветке `pipeline-data`, в `reports/<дата>-dry.md`, появится отчёт: что нашлось и что было бы добавлено. Если всё в порядке, дальше робот работает сам каждый день в 06:17 по Москве.

**Где хранится список источников.** Сайт публикуется из `main`, поэтому ветка `pipeline-data` на сайт не попадает, и имена источников не появятся ни в одном файле сайта. Но если репозиторий публичный, на GitHub видно всё: ветку, описания PR и issues. Конвейер старается не светить имена: в логах Actions каналы показаны номерами (`tg#1`), а отчёт в логи не выводится. Скрыть список от посетителей GitHub нельзя ни веткой, ни секретом `PIPELINE_SOURCES`: имена каналов есть в `state.json` (до какого поста прочитан канал), в отчётах в `pipeline-data` и в ссылках на посты в описании PR. Секрет лишь избавляет от файла `sources.json`. Если список должен быть тайным, репозиторий нужен приватный.

### Telegram

Читаются только **открытые** каналы, у которых есть веб-превью `t.me/s/<канал>`. Робот вежливый: одна страница за раз, пауза 1,5 с, представляется как `KudaIdemBot`. При первом запуске он берёт посты не старше 21 дня, дальше только новые.

### Instagram

Instagram не разрешает читать чужие страницы роботом, поэтому есть два пути.

**Путь 1 — официальный API (Business Discovery).** Он позволяет читать подписи к постам **публичных бизнес- и авторских аккаунтов**. Личные аккаунты так не читаются. Что нужно:

1. **Свой Instagram.** Переведите его в профессиональный («Бизнес» или «Автор») и свяжите со страницей Facebook (Instagram → Настройки → Аккаунт → Связанные аккаунты / «Страница»).
2. **Приложение Meta.** На developers.facebook.com создайте приложение (тип Business) и добавьте продукт «Instagram Graph API». Нужны разрешения `instagram_basic` и `pages_show_list`, а для некоторых аккаунтов ещё `pages_read_engagement` и `business_management`.
3. **Токен.** В Graph API Explorer получите токен пользователя с этими разрешениями и обменяйте его на долгоживущий (60 дней). Токен без срока можно выпустить для «системного пользователя» в Meta Business Suite. Положите токен в секрет `IG_ACCESS_TOKEN`.
4. **ID аккаунта.** `IG_USER_ID` — это числовой id **вашего** профессионального аккаунта, а не того, который читаете. Его можно узнать запросом `GET /me/accounts?fields=instagram_business_account` в Graph API Explorer.
5. **Список.** Впишите имена нужных аккаунтов в `"instagram"` в `sources.json`.

Долгоживущий токен истекает через 60 дней. Тогда в отчёте появится ошибка Instagram, и токен нужно обновить.

**Путь 2 — ящик (проще).** Создайте issue в этом репозитории с меткой **`источник`** и вставьте в него текст поста или ссылку, адрес, наводку на место. Можно в любом виде, например: «Открылась кофейня X на Покровке, 9, работает с 8 до 22». Робот разберёт issue при следующем запуске, а когда PR уже создан, ответит в issue, что сделал, и закроет его. Если запуск сорвался, issue остаётся открытым и разберётся в следующий раз. Issues от посторонних людей игнорируются: читаются только issues от владельца и соавторов репозитория. Метку `источник` создайте один раз: Issues → Labels → New label. Заявку про Петербург можно пометить второй меткой `спб` (или `Петербург`); без неё город определит модель по тексту, а если примет города нет — Москва.

## Как проверять PR

PR называется «Каталог: обновление <дата>» и помечен меткой `auto`. В описании лежит отчёт:

- **Новые места.** Откройте «на карте» и проверьте точку, адрес, метро и описание. Убедитесь, что фото показывает именно это место. Рядом указаны автор и лицензия фото.
- **Закрылись** (раздел в самом начале). Проверьте цитату из поста и ссылку на пост. Ниже перечислено, какие подборки при этом исчезнут.
- **События.** Сверьте дату, время, площадку и ссылку на билеты: домен ссылки показан открытым текстом.
- **Подборки.** Посмотрите, по каким остановкам план и в каком порядке: у каждой остановки название, тип и расстояние до следующей.
- **Обновления мест.** Их нужно перенести в `assets/places.js` (Петербург — `assets/places-spb.js`) руками, если они верны.
- **Отклонено и отложено.** Здесь всё, что робот не взял, с причиной. Обычно причина такая: нет адреса, адрес не нашёлся или неоднозначен, место 18+, модель не уверена.

Если что-то не так, поправьте или удалите строку прямо в `assets/auto.js` в этом PR. Каждое место, план и событие занимает отдельную строку. Если ошибочно добавлено фото, удалите поле `ph` и файлы `assets/ph/<id>.webp` и `assets/ph/t/<id>.webp`. Если всё неверно, закройте PR без слияния: посты уже отмечены прочитанными и не вернутся.

Пока PR открыт, следующие запуски **дописывают находки в тот же PR**. Ветка каждый раз пересобирается от свежего `main`: в неё переносится всё, что PR поменял (находки, фото и ваши правки в любых файлах, кроме номеров `?v=`), а изменения `main` после открытия PR не откатываются. В PR приходит комментарий с новым отчётом. Ваши коммиты в ветке PR сохраняются по содержимому, но сливаются в один коммит робота. Если изменения PR не накладываются на свежий `main`, робот откроет для новых находок отдельный PR, а старый оставит вам. PR из форков робот не трогает.

Номера версий `?v=` в HTML-страницах робот поднимает на 1 сам, чтобы браузеры загрузили свежий `auto.js`.

## Сколько стоит

Модель `claude-opus-5-5` стоит $4 за 1 млн входных токенов, $20 за 1 млн выходных и $0,20 за чтение кеша. Список каталога обоих городов (около 1 300 мест, примерно 35 тыс. токенов) кешируется на час, поэтому в одном запуске он оплачивается полностью один раз, а дальше почти бесплатно.

| | Оценка |
|---|---|
| Обычный день (5–10 каналов, 10–30 новых постов, 1–3 новых места) | ≈ $0,3–0,8 |
| Месяц ежедневных запусков | ≈ $10–25 |
| Первый запуск (до 40 постов с каждого канала) | ≈ $2–5 |
| День без новых постов | $0 (модель не вызывается) |

Точный расход за каждый запуск указан в конце отчёта (раздел «Модель»).

## PR давно не приходил

PR появляется только тогда, когда есть что добавить. Если его нет несколько дней:

1. Откройте **Actions → «Каталог — автообновление»**. Красный запуск значит, что модель не ответила (кончились деньги на счёте, неверный ключ), все источники одного вида недоступны или не сохранилось состояние. Жёлтые предупреждения показывают отдельные недоступные источники (`tg#2` — второй канал в списке).
2. Откройте ветку `pipeline-data`, папку `reports/`: там отчёт каждого запуска, даже без PR. Раздел «Источники» показывает ошибки каналов и Instagram (например, истёкший токен). Геокодеры и Wikimedia Commons бесплатны: у Яндекса есть бесплатный лимит запросов в сутки, у OpenStreetMap ограничение 1 запрос в секунду.

## Запуск на своём компьютере

Нужен Node.js 22.

```bash
cd pipeline && npm ci && cd ..
mkdir -p .pipeline-data && cp pipeline/sources.example.json .pipeline-data/sources.json
# впишите каналы в .pipeline-data/sources.json (папка в .gitignore)

node pipeline/run.mjs --state .pipeline-data --no-llm --max-posts 10       # только скачать и посчитать посты
ANTHROPIC_API_KEY=… node pipeline/run.mjs --state .pipeline-data --dry      # полный разбор, но без записи в assets/
ANTHROPIC_API_KEY=… node pipeline/run.mjs --state .pipeline-data            # как в Actions: пишет assets/auto.js и фото
```

Отчёт появится в `pipeline-report.md` (он в `.gitignore`) и в `.pipeline-data/reports/`. Все флаги смотрите в `node pipeline/run.mjs --help`. Самые нужные:

- `--dry`: ничего не пишет в `assets/` и не отмечает посты прочитанными;
- `--no-photos`: не искать фото;
- `--since-days N`: не разбирать посты старше N дней;
- `--record <папка>` / `--mock <папка>`: записать ответы модели и потом проиграть их без API.

Последняя строка вывода — `CHANGES=1` или `CHANGES=0`.

### Тесты

```bash
cd pipeline && node --test 'test/*.test.mjs'
```

Тесты не ходят в сеть: Telegram, геокодер, Commons и модель в них подставные, а работа идёт на временной копии `assets/`. На Node 22.14 форма `node --test test/` не работает, поэтому нужен шаблон в кавычках, как выше.

## Устройство

| Файл | Что делает |
|---|---|
| `run.mjs` | оркестратор: источники → модель → проверки → `assets/auto.js`, отчёт, состояние |
| `close-inbox.mjs` | ответ в issues ящика и их закрытие — последним шагом, после PR |
| `lib/sources/telegram.mjs` | веб-превью открытых каналов `t.me/s/…` |
| `lib/sources/instagram.mjs` | Instagram Graph API (Business Discovery) |
| `lib/sources/inbox.mjs` | ящик: issues с меткой «источник» |
| `lib/llm.mjs`, `prompts/` | запросы к модели: факты из постов, планы, выбор фото |
| `lib/catalog.mjs` | чтение каталога обоих городов, город места или плана, поиск дублей, id, проверка планов |
| `lib/geo.mjs` | города, геокодер, метро, округ или район |
| `lib/photos.mjs` | фото с Wikimedia Commons |
| `lib/autojs.mjs` | код слияния и формат `assets/auto.js` |
| `../.github/workflows/places-update.yml` | ежедневный запуск в GitHub Actions и PR |

Состояние (`state.json` в ветке `pipeline-data`) хранит:

- до какого поста прочитан каждый канал;
- какие посты уже разобраны (их ключи хранятся 120 дней);
- какие посты нужно повторить (модель не ответила, сбой геокодера, сработал лимит или кончилось время запуска);
- кеш геокодера.

Если модель трижды ответила, но не разобрала пост, он попадает в отчёт и больше не повторяется. Сбои связи и сервиса попыткой не считаются.

Когда с прошлого запуска в канале больше постов, чем `--max-posts`, берутся самые старые непрочитанные, а остальные приходят в следующие дни. Если отставание больше трёх таких порций, пропущенные номера постов видны в отчёте.

GitHub отключает расписание в репозиториях, где 60 дней не было коммитов. Если это случится, включите workflow снова на вкладке Actions.
